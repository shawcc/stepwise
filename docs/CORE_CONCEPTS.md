# WorkGraph 核心概念

## 一句话定义

WorkGraph 是面向 Agent 原生组织的递归目标执行系统：定义目标与成功，推导必要条件，选择举措并执行，再用证据审查结果、修正判断。

## 目标逻辑

### Objective｜目标

希望发生的变化，也是 WorkGraph 唯一的递归目标单元。

每个目标都有自己的关键结果、必要条件、下级目标、举措和审查闭环。下级目标使用相同结构，可以继续递归。

### Key Result｜关键结果

判断当前目标是否达成的结果标准。

关键结果必须可衡量或可验证，描述结果而不是任务。它留在当前层负责验收，不直接拆成下级目标。

### Necessary Condition｜必要条件

目标成立不可缺少的条件，属于待验证的因果判断。

判断方法：去掉这个条件，目标还能成立吗？如果不能，它才可能是必要条件。

必要条件按承担方式分类：

- 需要独立负责并继续拆解：转化为下级目标。
- 可以通过一组有边界的工作创造：交给举措。
- 外部且不可控制：保留为约束或假设。
- 被多个目标共同依赖：连接到共享目标。

### Child Objective｜下级目标

由需要独立负责的必要条件转化而来。

转化时必须明确责任主体、期望变化和工作边界，并定义属于它自己的关键结果。下级目标不是新实体，只是目标在递归关系中的位置。

## 工作事实

### Initiative｜举措

为创造一个或多个必要条件而选择的一组有组织的工作，例如项目、方案或专项。

举措包含负责人、范围、依赖、预期结果和行动，但不拥有独立的目标递归结构。如果一项举措需要自己的关键结果或继续向下拆解，它应升级为下级目标。

### Action｜行动

可以直接执行的最小工作单元，明确执行者、工具、输入、风险和完成状态。

### Outcome｜实际结果

行动或举措实际产生的结果。行动完成不等于目标达成，实际结果仍需证据证明，并与关键结果比较。

### Evidence｜证据

支持或反驳关键结果、必要条件和实际结果的可追溯事实。

证据必须记录来源、时间、权限和可信度，并贯穿全过程，而不是一个独立阶段。

### Decision｜决策

审查后形成的正式判断，包括接受、调整、重做或停止，以及对应理由、责任人和影响范围。

## 流程与视图

以下概念不是独立事实对象，而是由工作事实组成的过程或视图。

### Route｜路线

下级目标、举措、行动及其依赖关系的组合，说明如何创造必要条件。

### Execution｜执行

举措和行动的运行过程，包括状态变化、实际结果和证据回填。

### Review｜审查

用证据核验关键结果、必要条件和实际结果，并形成决策。审查不是事后总结，而是可以触发调整或重做的控制回路。

## 结果与过程

### Work Entry｜工作入口

组织级入口是工作图谱，用来发现和进入目标；具体工作的主入口是 Objective 文档。IM、通知和待办只负责把注意力路由回目标，不再承载工作事实本身。

探索、事故和临时事项也需要先建立临时目标或运行目标，再进入同一套协作、执行和回写闭环。

### Objective Workspace｜目标工作台

以文档形式保存当前已确认的工作事实，是人和 Agent 开展具体工作的共同入口。正文只呈现当前结果，不堆积形成过程。

目标文档不是与图谱并列的第二份数据。它是一个 Objective 在当前版本下的权威工作视图；底层事实、关系、权限和版本仍由工作图谱统一管理。

### Process Deliberation｜过程推演

锚定到目标文档的具体章节或对象，保存讨论、问题、AI 分析、修改提案、执行更新、审查意见和决策请求。

过程推演是人和 Agent 共同工作的空间，底层是结构化事件流。AI 可以读取上下游、回应质疑、执行检查和提交提案，但默认不能直接改写正式文档。

每条关键结论都必须能反向追溯过程：悬停结论可直接打开过程推演；已有过程可在正文中折叠预览。推演空间同时展示历史事件和总结，包括推演轮次、AI 分析、修改提案、正式版本及结论变化。

这里保存的是可审查的工作依据、提案和决策，不是模型不可验证的内部思维链。

### Version Record｜版本记录

保存每次确认前后的差异、依据、参与者和时间。过程推演产生提案，提案被确认后写入目标文档并生成新版本；历史过程继续保留，用于解释结果为什么形成以及从哪里重做。

当前原型只把工作图谱和目标工作台作为一级入口。依赖、证据、监控和时间线是同一批工作事实的派生观察视图，保留能力但不与主入口并列。

## 治理信息

所有工作事实还必须带有责任主体、权限、治理规则、时间、来源和版本。这些信息不属于目标递归层级，但决定人和 Agent 能否读取、执行、确认或修改工作。

## 核心关系

```text
目标 Objective
├── 关键结果 Key Results：怎样算成功
├── 必要条件 Necessary Conditions：成功依赖什么
│   ├── 下级目标 Child Objective：独立负责并继续递归
│   └── 举措 Initiative：组织一组工作创造条件
│       └── 行动 Action：直接执行
│           └── 实际结果 Outcome：实际发生了什么
└── 证据 Evidence：支持或反驳结果与判断
    └── 审查 Review：比较证据与关键结果
        └── 决策 Decision：接受、调整、重做或停止
```

路线是下级目标、举措、行动和依赖关系的视图；执行是行动产生实际结果和证据的过程；审查用证据形成决策并回流上游。

## 六条规则

1. 目标是唯一的递归单元，不再区分 Goal、SubGoal 或 Work Unit。
2. 关键结果属于测量侧，只验收它所属的目标。
3. 必要条件属于原因侧，根据承担方式转化为下级目标、举措、约束或共享目标。
4. 举措组织行动；需要独立关键结果和继续拆解时，举措升级为下级目标。
5. 行动完成不等于目标达成，必须由证据核验关键结果，并由审查形成正式决策。
6. 目标工作台保存当前结果，过程推演承载共同工作，版本记录保存已确认的变化。
